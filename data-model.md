# Data Model: быстряга

Все типы — panos-код (иллюстративный, финальные имена полей могут
уточниться в tasks.md/при реализации).

## `Валидируемое` (`валидация.pns`)

```
/// Реализуйте на структуре тела запроса, чтобы получить авто-валидацию
/// (быстряга.отправить_пост/... вызывает .проверить() после разбора
/// JSON, до вызова обработчика). Структуре без реальной валидации
/// достаточно вернуть Опция.Нет() всегда.
экспорт тип Валидируемое = интерфейс
	функ проверить(это: Валидируемое) -> Опция(Строка)
конец
```

## `Отклик(О)` (`приложение.pns`) — явный статус-код (FR-007)

```
/// Оборачивает тело ответа явным HTTP-статусом — используйте, когда
/// нужен код, отличный от 200 (например 201 при создании ресурса).
/// Обработчик может вернуть либо голое О (подразумевает 200), либо
/// Отклик(О) (явный статус) — обе формы поддержаны регистрацией.
экспорт тип Отклик[О] = структура
	статус: Число
	тело:   О
конец
```

## `МетаданныеМаршрута` (`приложение.pns`)

```
экспорт тип МетаданныеМаршрута = структура
	метод:   Строка
	путь:    Строка
	// Заполняется только для маршрутов, зарегистрированных через
	// *_со_схемой-варианты — иначе массив пуст, документация.pns
	// отдаёт путь+метод без деталей (FR-010).
	поля_тела:   Массив(валидация.ПолеСхемы)
	поля_ответа: Массив(валидация.ПолеСхемы)
конец
```

## `ПолеСхемы`/`ОписаниеСхемы` (`валидация.pns`, не `документация.pns`)

Живут в валидация.pns вместе с ТелоJSON/ОтветJSON/Валидируемое, не в
документация.pns — иначе циклическая зависимость (МетаданныеМаршрута
в приложение.pns ссылается на ПолеСхемы, документация.pns уже
импортирует приложение.pns).

```
/// Описание одного поля структуры для OpenAPI JSON Schema —
/// заполняется реализацией ОписаниеСхемы.
экспорт тип ПолеСхемы = структура
	имя:         Строка
	тип_json:    Строка   // "string" | "number" | "boolean" | "object" | "array"
	обязательно: Булево
конец

/// Опционально реализуйте на структуре тела/ответа для детальной
/// OpenAPI-схемы (см. приложение.pns's *_со_схемой-регистрацию) — без
/// этого интерфейса маршрут всё равно попадает в /openapi.json, просто
/// без развёрнутой схемы тела.
экспорт тип ОписаниеСхемы = интерфейс
	функ поля_схемы() -> Массив(ПолеСхемы)
конец
```

## `Middleware` (`middleware.pns`, US3)

```
/// Продолжение цепочки middleware — вызовите, чтобы передать запрос
/// дальше (следующему middleware или, для последнего звена, самому
/// Маршрутизатору). НЕ вызывайте, чтобы коротко замкнуть цепочку
/// (например при отказе авторизации) — тогда middleware сам
/// формирует ОтветСервера.
экспорт тип Далее = функ(ЗапросМаршрута) -> ОтветСервера

экспорт тип Middleware = функ(ЗапросМаршрута, Далее) -> ОтветСервера
```

## `Приложение` (`приложение.pns`) — корневой тип

```
/// Типизированная надстройка над http.Маршрутизатор — регистрируйте
/// маршруты методами получить/отправить_пост/..., затем .запустить(порт).
экспорт тип Приложение = структура
	маршрутизатор:      http.Маршрутизатор
	маршруты_докс:      Массив(МетаданныеМаршрута)
	middleware_список:  Массив(Middleware)
	хуки_старта:        Массив(функ() -> Пусто)
	хуки_остановки:     Массив(функ() -> Пусто)
конец

/// Создаёт пустое Приложение.
экспорт функ приложение() -> Приложение
	Приложение(http.маршрутизатор(), массив(), массив(), массив(), массив())
конец
```

`Приложение` — структура, то есть ССЫЛОЧНЫЙ тип в этой VM (тот же
принцип, что `http.Маршрутизатор` уже документирует у себя, см.
`http.pns` doc-комментарий над `тип Маршрутизатор`) — методы
регистрации мутируют поля напрямую, порядок вызовов относительно
`.запустить()` не важен для корректности.

## Ошибка (JSON-тело для 400/422)

Не отдельная структура — переиспользуем существующий `json.объект(...)`
напрямую внутри `валидация.ответ_ошибки`, без нового типа:
```
json.объект(&.{("ошибка", json.Значение.Строка(сообщение))})
```
